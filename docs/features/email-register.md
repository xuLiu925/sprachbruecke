# 邮箱注册和找回密码

## 功能介绍

- **注册**：填用户名、密码、邮箱 → 点“发送验证码” → 把邮件里的 6 位验证码填进去 → 注册。验证码 10 分钟内有效。
- **登录**：用户名或邮箱都可以。
- **忘了密码**：在登录页点“忘了密码”，输入邮箱，收验证码，设置新密码后直接登录，其他已登录的设备会下线。没绑定邮箱的账号，只能找管理员重置密码。
- **绑定邮箱**：老账号在「我的」页绑定邮箱，绑定后也能更换。绑定和更换都要输当前登录密码（防止别人拿到已登录的手机，把邮箱换成自己的再找回密码），更换后给旧邮箱发一封通知（新邮箱打码显示）。
- 管理员的成员列表里会显示每个人的邮箱。

### 注册方式

| 方式 | 什么时候用 |
|---|---|
| `email` 邮箱验证码 | 配置了发信时的默认方式 |
| `invite` 邀请码 | 没配置发信时的默认方式（和以前一样） |
| `open` 不用验证 | 只在测试时用 |

在服务器上设置环境变量 `REGISTER_MODE` 可以指定注册方式，比如暂停公开注册时设成 `invite`。第一个用户（管理员）注册时什么都不用填。

**邀请链接**（邮箱方式下的隐藏入口）：管理员在「我的」页点“生成邀请链接”，自动复制 `网址/?invite=邀请码`。打开链接，注册页显示已填好的邀请码，不用邮箱，只填用户名和密码。普通注册页看不到邀请码。用来建测试账号，或者给收不到验证邮件的人开账号。这样注册的账号没有邮箱，忘了密码要管理员重置，登录后可以自己绑定邮箱。

## 详细设计

### 涉及的文件

| 文件 | 内容 |
|---|---|
| `email_codes.py` | 发信（SMTP）、验证码、发送频率限制 |
| `auth.py` | 注册方式 `register_mode()`；注册、登录、找回密码、绑定邮箱的接口 |
| `database.py` | `users.email`（迁移）、`email_codes`、`mail_log` |
| `static/index.html`、`static/js/core.js` | 登录页分登录、注册、忘了密码三块；`sendCode()` 发验证码后倒数 60 秒 |
| `static/js/home.js` | 「我的」页绑定或更换邮箱 |

### 接口

| 方法 路径 | 说明 |
|---|---|
| GET `/api/me` | 没登录时多返回 `register`（注册方式），登录后多返回 `email` |
| POST `/api/register/code` | `{username, email}`：先检查用户名和邮箱能不能用，再发验证码 |
| POST `/api/register` | 邮箱方式要带 `{email, code}`，邀请码方式要带 `{invite}`；邮箱方式下带了 `invite` 就按邀请码处理（邀请链接），不看邮箱 |
| POST `/api/login` | `username` 里有 `@` 就按邮箱查 |
| POST `/api/password/forgot` | `{email}`：没有这个邮箱也返回成功（不让人试出谁注册过），但不发信 |
| POST `/api/password/reset` | `{email, code, new}`：设置新密码并登录 |
| POST `/api/email/code`、POST `/api/email` | 登录用户绑定邮箱：发验证码、确认 `{email, code, password}`（密码错和改密码共用限速；有旧邮箱时发通知，发不出去不影响更换） |

### 数据

- `users.email`：存小写，唯一（`idx_users_email`，空值不算）。老数据库启动时用 `ALTER TABLE` 加这一列，原有数据不变。
- `email_codes(email, purpose, code_hash, expires_at, tries)`：每个邮箱每种用途只留最新一个，只存哈希。用过就删，输错 5 次作废。
- `mail_log(email, purpose, sent_at, ip)`：用来限制发送频率。同一个邮箱 60 秒内只能发一次、一小时最多 5 次；同一个 IP 一小时最多 10 封、一天最多 20 封（防止一个人换几十个邮箱把全站额度刷光；国内手机网络很多人共用出口 IP，所以不设太小）；全站每天最多 200 封（Gmail 免费每天约 500 封）。
- 登录失败限速（内存里，重启清零），10 分钟内：同一用户名 + 同一 IP 最多失败 8 次；同一 IP 最多 30 次；同一用户名所有 IP 加起来最多 100 次。这样别人故意输错锁不住你的账号，换着用户名撞密码也会被拦。
- IP 取法（`helpers.py` 的 `client_ip()`）：Worker 填的 `X-Real-IP` > `CF-Connecting-IP` > 直连地址。

### 发信配置

服务器上的 `~/sprachbruecke/.mail_config`（不进版本库）：

```
{"user": "你的Gmail地址", "password": "应用专用密码"}
```

也可以用环境变量 `MAIL_USER`、`MAIL_PASSWORD`。默认用 `smtp.gmail.com:465`，可以加 `host`、`port` 换成别的服务。发信失败时，接口返回“邮件没发出去”，原因写进 `server.log`。

### 关键取舍

- **先验证邮箱再建账号**：没验证的邮箱不会存进数据库，乱填的邮箱建不了账号。
- **用户名不能有 `@`**：这样登录时看到 `@` 就知道是邮箱。
- **不做手机号注册**：发短信要花钱。

### 已知限制

- QQ、163 邮箱有时会把验证码放进垃圾邮件，注册页上已经提示用户去垃圾邮件里找。
- 发信用的是 Python 自带的 SMTP 库，发一封要 1–2 秒，这期间这个请求会等着。
- 还没做注销账号和导出数据（CLAUDE.md 待办）。
- 快速隧道链接（`*.trycloudflare.com`）本身能直接访问，绕过 Worker 的人可以自己填 `X-Real-IP`，按 IP 的限制挡不住这种专门伪造的人；同一用户名 100 次的总上限还在。
