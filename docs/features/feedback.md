# 意见反馈和报错汇总

## 功能介绍

### 所有用户：意见反馈

「我的」页有“意见反馈”，可以写页面打不开、按钮没反应、想要什么功能等问题，最多 1000 字，每人每天最多 20 条。

题目、讲解、构词有错时，还是用那里的“⚠️ 报错”，这样管理员能直接知道是哪道题、哪句话。

### 管理员：反馈和报错

「我的」页的“反馈和报错”把所有还没处理的内容放在一个列表里，新的在前：

| 类型 | 来自 | 显示的内容 |
|---|---|---|
| 意见反馈 | 「我的」页 | 写的内容 |
| 句子讲解、替换练习 | 讲解面板的报错 | 原句 |
| 语法题库 | 题库题的报错 | 题目、答案、知识点 |
| 自动出的题 | 定冠词、不定冠词、动词、复数等练习的报错 | 词和题目，能点“单词卡” |
| 构词解释 | 构词的报错 | 词 |

每条都写了谁报的、哪天报的。处理完点“已处理”：

- 报错会删掉，和语法题库管理页里“清除报错”的效果一样。讲解、构词重新生成时本来也会清掉报错。
- 意见反馈只记下处理时间，不再显示，数据库里留着记录。

## 详细设计

### 涉及的文件

| 文件 | 内容 |
|---|---|
| `feedback.py` | 写反馈、管理员列表、已处理 |
| `database.py` | 新表 `feedback` |
| `static/index.html`、`static/js/home.js` | 「我的」页的反馈框和管理员列表（`loadReports()`） |
| `tests/test_api.py` | 权限、校验、列表内容、已处理 |

### 接口

| 方法 路径 | 说明 |
|---|---|
| POST `/api/feedback` | `{text, page}`，登录用户；`page` 可选，记在哪个页面写的（前端暂时不传） |
| GET `/api/admin/feedback` | 管理员：`items`，每条有 `type`（`feedback` / `report`）、`kind_name`、`target`、`reason`、`user`、`created_at`；反馈带 `id`、`page`，报错带 `kind`、`key`，自动出的题带 `word_id` |
| POST `/api/admin/feedback/done` | 管理员：`{type: feedback, id}` 或 `{type: report, kind, key}`，返回 `done` = 处理了几条 |

### 数据

- 新表 `feedback(id, user_id, text, page, created_at, done_at)`，用户删掉后 `user_id` 变成空。`CREATE TABLE IF NOT EXISTS`，老数据库启动时自动建，不用迁移。
- 报错不加表，直接读现有的 `content_reports`，显示时按 `kind` 查对应的内容：讲解和替换练习查 `sentence_notes` / `sentence_drills` 的原句，语法题查 `grammar_questions`，自动出的题查 `words`（报错内容存的是“题目｜原因”，显示时拆开），构词的键就是词。内容已经删掉时显示“内容已被删掉或重新生成”。

### 关键取舍

- **只有单词能直接打开**：句子讲解、语法题没有能单独打开的页面，所以列表里直接显示原句和题目。
- **报错处理完就删**：和各处原有的做法一致，`content_reports` 每个内容只留最新一条，不保留历史。

### 已知限制

- 反馈里不记设备和浏览器，用户写反馈时也在「我的」页，看不出问题出在哪个页面，要靠用户自己写清楚。
- 处理后没法回复用户，要私下告诉他。
- 新反馈没有提醒，管理员要自己打开「我的」页看。
