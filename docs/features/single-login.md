# 单设备登录

## 功能介绍

一个账号同时只能在一个设备上登录。

- **在新设备登录：** 之前登录的设备自动下线。旧设备下一次操作时回到登录页，提示“这个账号已在别的设备登录，请重新登录”。
- **管理员重置密码：** 这个账号所有已登录的设备都会下线，要用临时密码重新登录。
- **自己改密码：** 当前设备保持登录，但会换一个新令牌，改密码前的会话（比如被偷走的 cookie）全部作废。
- **退出登录：** 这次登录作废。

这样朋友不能共用一个账号（共用会让学习进度和今日学习的数字混在一起），密码泄露时重新登录一次就能把别人挤下线。

## 详细设计

### 涉及的文件

| 文件 | 内容 |
|---|---|
| `auth.py` | `login_ok()` 发令牌，`check_login()` 每次请求核对，`drop_login()` 作废 |
| `tests/test_api.py` | 两个设备轮流登录、重置密码、退出 |

### 做法

- 登录或注册时生成一个随机令牌，存到 `user_settings`（`key = login_token`），同时写进会话 cookie。
- `check_login()` 用 `before_app_request` 注册，所有请求都会经过。会话里的令牌和数据库里的不一样，就清掉会话：`/api/` 接口返回 401 和提示文字，`/api/me` 返回未登录。前端 `api()` 收到 401 后显示登录页。
- 重置密码和退出时删掉数据库里的令牌，所有设备的令牌都对不上了。
- 没有新表，用现有的 `user_settings`，不用迁移。

### 关键取舍

- **新设备挤掉旧设备**，不是“已经登录了就不让新设备登录”。否则旧设备忘了退出（比如在别人电脑上登过），自己就再也登不进去了。
- **功能上线前登录的设备：** 会话里和数据库里都没有令牌，先放行，不会在部署后被全部踢下线。只要这个账号在任何设备上登录一次，其他设备就下线了。
- 每次请求多查一次数据库，按主键查，开销很小。

### 已知限制

- 自己在电脑和手机上同时用也不行，要来回登录。以后可能改成“允许多个设备，可以在‘我的’页让某个设备下线”（见 CLAUDE.md 待办）。
- 旧设备只有在发请求时才发现自己下线了，页面上原有的内容还在，直到下一次操作。
